# brigd

Локальный таск-трекер для **Codex CLI и Claude Code**. Создавайте задачи, задавайте интервалы, отвечайте на вопросы агента в карточке и сохраняйте историю каждого запуска.

**Bun · Svelte 5 · SQLite.** Один сервис, без отдельной очереди и без прямых вызовов API моделей. Браузер открывает интерфейс на вашем компьютере. Расписание работает, только пока компьютер включён и сервис brigd запущен.

## Обновление с Trackt

brigd — новое имя того же приложения. Обновляйте код в **существующей папке**, после остановки старого процесса; переносить или переименовывать папку, SQLite или рабочие проекты не нужно. Команды `bun run build` / `bun run start` и порт `4310` прежние. Сохраните прежние переменные окружения и проброс порта, если запускаете сервис в уже настроенном контейнере или через VS Code.

Репозиторий теперь находится по адресу [olntn/brigd](https://github.com/olntn/brigd). В существующей папке установки обновите адрес `origin`:

```sh
git remote set-url origin https://github.com/olntn/brigd.git
```

Эта команда меняет только адрес Git-репозитория. Папку установки и данные оставьте на месте.

- База обычного запуска по-прежнему `data/trackt.sqlite`, демо — `data/demo.sqlite`. Явно заданный `TRACKT_DB` продолжает работать. Новая пустая папка проекта без прежней базы покажет пустой список, поэтому для обновления не нужен повторный clone.
- Все серверные переменные `TRACKT_*` поддерживаются; новые `BRIGD_*` — их аналоги с приоритетом, если заданы оба имени. `PORT` не меняется.
- В Compose сохранены проект и сервис `trackt`, тома `trackt-data` / `trackt-cli-home`, пути базы и домашней папки CLI. Это намеренная совместимость, чтобы задачи и вход в CLI сохранились. Не меняйте Compose project name при обновлении.
- Тема из `trackt.theme` копируется в `brigd.theme` в том же браузере и на том же адресе. Старое значение не удаляется; действительное новое имеет приоритет. При смене домена, протокола или порта браузер использует отдельное хранилище.
- Профили работников и аватары добавляются в существующую SQLite автоматически. Старые задачи остаются без назначенного работника и используют свой прежний CLI; старые запуски сохраняют сессии и историю. Для них уровень усилий остаётся по умолчанию CLI, стиль общения не добавляется. Перед обновлением сделайте резервную копию базы при остановленном сервисе.

## Быстрый старт

Для Linux-контейнера начните с [Docker Compose: установка, тома и вход в CLI](docs/container.md). В образе есть оба CLI, а данные и сессии сохраняются в отдельных томах.

Для запуска без контейнера нужны [Bun](https://bun.sh/docs/installation) **1.3+** (проверено на 1.4.2) и Git. Для реальных задач установите хотя бы один CLI: [Codex](https://learn.chatgpt.com/docs/codex/cli) или [Claude Code](https://code.claude.com/docs/en/overview). Войдите в нужный CLI самостоятельно в терминале и убедитесь, что обычный запуск работает. brigd не просит API-ключи и не выполняет вход за вас.

```sh
git clone https://github.com/olntn/brigd.git brigd
cd brigd
bun install --frozen-lockfile
bun run doctor
bun run build
bun run start
```

Откройте **http://127.0.0.1:4310**. Терминал нужно оставить открытым. `Ctrl-C` корректно останавливает сервис и активные CLI-процессы.

`doctor` проверяет наличие CLI и поддержку нужных флагов через `--help`. Он не отправляет платные запросы и не проверяет вход/подписку. CLI должен быть доступен в `PATH` того терминала, из которого запускается brigd.

### Сначала попробовать без запросов к моделям

```sh
bun run build
bun run demo
```

Откройте тот же адрес. В интерфейсе показана метка **Демо**. Создайте задачу с любой инструкцией и существующей абсолютной рабочей папкой:

- Обычный текст: тестовый агент завершает запуск
- Добавьте `[ask]`: агент задаёт уточняющий вопрос; ответ продолжает ту же тестовую сессию
- Добавьте `[blocked]`: демонстрация блокировки разрешений
- Добавьте `[fail]`: демонстрация ошибки

Это симуляция. Реальные CLI не запускаются, файлы рабочего проекта не меняются, запросов к модели нет. Демо использует отдельную базу `data/demo.sqlite`; обычный запуск — `data/trackt.sqlite`.

### Первая настоящая задача

1. Запустите `bun run start`, выберите **Новая задача**.
2. Укажите понятную инструкцию, нужный CLI и абсолютный путь к проекту. Для Codex используйте доверенный Git-репозиторий; brigd не отключает проверку репозитория.
3. Для первого теста выберите **Вручную**, сохраните и нажмите **Запустить**. Начните с безвредной задачи: «Кратко опиши структуру проекта, ничего не меняй».
4. Если агент запросит уточнение, ответьте в карточке. Кнопка продолжения передаст ответ в сохранённый ID сессии.
5. Для регулярной работы включите интервал и время первого запуска. Расписание работает локально, даже когда вкладка закрыта, пока запущен сервис.

Реальные запуски используют ваш CLI, его текущий аккаунт и лимиты/тариф. Комментарий к задаче сохраняется как заметка; для передачи уточнения агенту используйте поле ответа активного запуска.

## Работники

В разделе **Работники** создайте профиль: имя, аватар, Codex или Claude Code, уровень усилий и необязательный стиль общения. В форме задачи назначьте работника; провайдер берётся из его профиля. Без работника можно по-прежнему выбрать CLI напрямую.

- Имя и аватар помогают узнавать исполнителя в задачах и истории. Они не предоставляют разрешений и не передаются как системные инструкции.
- Стиль общения — до 4 000 символов, например «Отвечай по-русски, кратко; перечисляй проведённые проверки». Он передаётся внутри обычного текста задания как JSON-строка с пометкой недоверенного необязательного предпочтения. Он не меняет задачу, формат результата или нативные разрешения CLI. Не помещайте в профиль пароли и другие секреты.
- **По умолчанию CLI** не добавляет флаг усилий и сохраняет настройки провайдера. Codex поддерживает выбор `low`, `medium`, `high`, `xhigh`; Claude Code — `low`, `medium`, `high`, `xhigh`, `max`. brigd передаёт Codex параметр `-c model_reasoning_effort="…"`, Claude — `--effort …`, без замены одного уровня другим.
- Перед запуском проверяется помощь установленного CLI. Явный уровень усилий для Codex требует `--config` и `--strict-config` на путях нового запуска и продолжения; строгая проверка включается, чтобы неизвестная настройка не была проигнорирована. Для Claude проверяются `--effort` и перечисленные им уровни. Если поддержки нет, запуск завершится понятной ошибкой: обновите CLI или выберите уровень по умолчанию.
- Выбранный уровень — запрос к CLI. Фактические возможности зависят от модели, аккаунта и настроек провайдера. В частности, Claude может ограничить уровень согласно модели или правилам организации, в том числе без отдельного уведомления в `stream-json`. brigd не меняет модель или лимиты аккаунта и не обещает одинаковую глубину работы разных моделей.
- Аватар загружается локально: интерфейс уменьшает изображение до 256 px; сервер принимает PNG, JPEG или WebP до 256 КиБ, размером не более 1024 × 1024. Байты сохраняются в той же SQLite, без внешнего хостинга. Смена аватара не изменяет фото в старых запусках; внешние URL и SVG не используются.
- Архив скрывает работника из нового назначения. Уже назначенные задачи и их расписание продолжают работать; работника можно восстановить. Чтобы остановить будущие запуски, отдельно поставьте расписание задачи на паузу.

При старте сохраняется неизменяемый снимок имени, аватара, провайдера, уровня усилий и стиля. Продолжение после вопроса или перезапуска сервиса использует тот же снимок и точную сессию. Редактирование и архивирование профиля не меняют уже начатый запуск; следующий новый запуск использует актуальные настройки назначенного работника. Для уровня «по умолчанию CLI» фиксируется отсутствие переопределения, а не внутренние настройки модели: они остаются под управлением провайдера.

Поддержка параметров сверена с [конфигурацией Codex](https://learn.chatgpt.com/docs/config-file/config-reference), [CLI Claude Code](https://code.claude.com/docs/en/cli-reference) и [правилами effort в Claude](https://code.claude.com/docs/en/model-config#adjust-effort-level). Проверка `--help` не вызывает модель и не проверяет доступность уровня на вашем аккаунте.

## Что умеет MVP

- Доска и список задач, поиск, фильтрация по агенту
- Именованные работники с локальными аватарами, настройками усилий/общения и неизменяемой историей профиля для каждого запуска
- Светлая и тёмная темы: «Настройки» в боковом меню; выбор сохраняется в этом браузере
- Адаптивная раскладка для узких экранов, увеличенного текста и масштаба браузера
- Название, инструкция, провайдер, рабочая папка, ручной запуск или интервал, первый запуск, пауза расписания
- Карточка с комментариями, вопросами, результатами и отдельной историей запусков
- Продолжение **точной** сессии Codex/Claude, отмена активного запуска
- SQLite WAL, атомарный захват планового запуска и уникальность «задача + плановое время»
- Один незавершённый запуск на задачу, включая ожидание ответа и прерывание
- Восстановление после перезапуска без автоматического повтора потенциально выполненных действий
- Демо-адаптер, автоматические тесты и браузерные сценарии

## Расписание и восстановление

Интервалы отсчитываются от первого запуска. Если сервис спал несколько часов, выполняется максимум **один последний актуальный** интервал; пропущенная очередь не догоняется. Если задача уже выполняется или ждёт ответа, её очередные интервалы пропускаются.

Пауза останавливает будущие автоматические запуски. Активный запуск она не отменяет; ручной запуск по-прежнему доступен. Изменения инструкции, папки, провайдера, назначения и профиля работника применяются только к новым запускам. Текущий запуск хранит собственный снимок настроек.

После остановки сервиса выполнявшиеся задачи помечаются как **Прервано**. Они не запускаются автоматически. Если ID сессии уже сохранён, можно продолжить после явного подтверждения, что старый CLI-процесс остановлен. После аварийного завершения процесса brigd проверьте это самостоятельно: осиротевший CLI может ещё работать. Если ID не успел сохраниться, отмените прерванный запуск и начните новый после проверки результатов. Ожидающие ответа сессии переживают перезапуск без потери состояния.

Отмена переводит запуск в **Останавливается** и отправляет сигнал CLI (на POSIX — группе процессов). До завершения остановки задача остаётся занята; затем статус меняется на **Отменено**. Уже выполненные изменения не откатываются. Не запускайте разные задачи на изменение одних и тех же файлов одновременно: блокировка применяется к задаче, а не ко всей рабочей папке.

## Разрешения и безопасность

- Без контейнера сервис слушает только `127.0.0.1`. В Compose он слушает `0.0.0.0` внутри контейнера, а порт хоста опубликован только на `127.0.0.1`. Не публикуйте порт в интернет и не ставьте перед ним публичный reverse proxy. Авторизации и многопользовательского режима в MVP нет.
- API проверяет `Host`, `Origin` и `Sec-Fetch-Site`; изменения принимаются только как ограниченный по размеру JSON из локального интерфейса. CORS не включён.
- CLI запускаются через массив аргументов `Bun.spawn`, без shell-интерполяции.
- Codex работает с `workspace-write` и обычным запросом разрешений; Claude — с обычным режимом разрешений. brigd не добавляет bypass-флаги и не выдаёт широкие разрешения автоматически.
- Вопросы по задаче и системные запросы разрешений различаются. Нативные интерактивные подтверждения CLI не поддерживаются в карточке. Такой запуск получает **Блокировка**, а не ложный успех. Проверьте сессию в терминале провайдера и его локальные настройки; после устранения причины запустите новую попытку. Не вводите пароли или ключи в ответы.
- CLI загружают свою обычную локальную/проектную конфигурацию, правила, плагины и доверенные инструменты. brigd не изолирует их от вашей конфигурации и не является границей безопасности. Используйте доверенные рабочие папки и инструкции.
- Сырой stdout/stderr, рассуждения и вывод инструментов не записываются в комментарии. Сохраняются краткие события, явные вопросы и финальный результат. Не указывайте секреты в инструкции: инструкции и ответы хранятся в локальной SQLite, а при реальном запуске передаются CLI.
- Один ход ограничен 10 минутами, 8 МиБ суммарного вывода и 1 МиБ на JSONL-строку. Превышение — ошибка, не завершение задачи.
- База не шифруется. По умолчанию каталог данных приватный на POSIX. Храните его в защищённом локальном профиле и делайте резервную копию при остановленном сервисе.

## CLI-протокол

Codex: `exec --json`, `thread.started` сохраняет `thread_id`, продолжение использует `exec resume` с этим ID. Claude: `-p --output-format stream-json --verbose`, сохраняется `session_id`, продолжение — `--resume` с этим ID. Адаптер проверяет установленные `--help` перед использованием флагов; JSON Schema включается, если поддерживается.

Агент завершает ход строгим объектом:

```json
{
  "status": "needs_input",
  "summary": "Нужно уточнить критерий результата.",
  "questions": ["Для какой аудитории подготовить обзор?"]
}
```

Допустимы `needs_input`, `completed`, `blocked`. Только `needs_input` содержит вопросы. Нулевой exit code сам по себе не означает успех: нужны ID сессии, финальное событие провайдера и валидный объект. Непонятный или повреждённый ответ становится видимой ошибкой протокола.

Документация: [Codex non-interactive](https://learn.chatgpt.com/docs/non-interactive-mode), [Claude headless](https://code.claude.com/docs/en/headless), [Claude CLI reference](https://code.claude.com/docs/en/cli-reference).

## Разработка и тесты

```sh
bun run dev          # Vite: http://127.0.0.1:5173, API: 4310
bun run dev:demo     # то же, без настоящих CLI
bun run verify      # typecheck + Bun tests + production build
bun run test:smoke  # HTTP, реальные процессы сервиса, restart/SIGKILL; только mock
bunx playwright install chromium
bun run test:e2e    # production browser tests, только mock
```

Браузерные тесты дополнительно проверяют сохранение и перенос темы с Trackt, синхронизацию между вкладками, недоступное хранилище браузера, размеры экрана от 320 до 1440 px, текст 200% и длинное содержимое карточек и форм.

Браузерные тесты используют порт 4318 и отдельную базу в `test-results/`. В CI запускаются те же проверки. Для уже установленного Chromium можно указать `PLAYWRIGHT_CHROMIUM_EXECUTABLE`.

Переменные окружения сервера (для каждого `BRIGD_*` поддерживается прежний `TRACKT_*`; новое имя имеет приоритет):

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `BRIGD_MODE` | `cli` | `cli` или `mock` |
| `BRIGD_DB` | `data/trackt.sqlite` или `data/demo.sqlite` | Файл SQLite относительно проекта либо абсолютный путь |
| `PORT` | `4310` | Порт production-сервиса; dev использует 4310 |
| `BRIGD_HOST` | `127.0.0.1` | В контейнере `0.0.0.0`; нужны два явных allowlist ниже |
| `BRIGD_ALLOWED_HOSTS` | `127.0.0.1:4310,localhost:4310` | Разрешённые Host, через запятую, без wildcard |
| `BRIGD_ALLOWED_ORIGINS` | `http://127.0.0.1:4310,http://localhost:4310` | Точные Origin интерфейса, через запятую |
| `BRIGD_DEFAULT_CWD` | Текущая папка сервиса | Начальное значение рабочей папки в форме |
| `BRIGD_DEV` | `0` | `1` для dev-сервера; `bun run dev` задаёт автоматически |

Переменные самого Compose (`TRACKT_MODE`, `TRACKT_UID`, `TRACKT_GID`, `TRACKT_PROJECTS_DIR`) сохраняют прежние имена; подробности в [инструкции контейнера](docs/container.md).

Структура: `src/` — Svelte UI, `server/store.ts` — данные/расписание, `server/engine.ts` — жизненный цикл, `server/adapter.ts` — CLI/mock, `server/protocol.ts` — валидация событий, `tests/` и `e2e/` — проверки.

## Проверенные границы

Локальные проверки ядра и сборки выполняются на Linux с Bun 1.4.2. Playwright-сценарии и Docker smoke включены в CI; статус конкретного коммита смотрите в GitHub Actions. CLI проверяются через `--help` без запросов к модели. Тесты CLI-протокола и процессов используют искусственные события/безвредные процессы. Авторизованные платные запросы к реальным моделям при разработке не выполнялись.

Основная целевая среда — Linux-контейнер. macOS и нативная Windows пока не заявлены как end-to-end проверенные. На Windows можно использовать Docker Desktop с Linux-контейнером; рабочая папка в карточке всегда задаётся путём внутри контейнера, например `/workspace/projects/my-project`.

MVP не устанавливает фоновую системную службу, не отправляет push-уведомления, не синхронизирует данные между устройствами и не восстанавливает автоматически результаты действий, выполненных вне brigd.
