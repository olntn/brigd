# Trackt в Linux-контейнере

Один контейнер содержит Trackt, Bun, Codex CLI и Claude Code. Интерфейс доступен только на `http://127.0.0.1:4310` хоста. Для проверки интерфейса аккаунты и платные запросы не нужны. Реальные задачи требуют вашего самостоятельного входа хотя бы в один CLI и доступного ему тарифа/лимитов.

## 1. Собрать и запустить

Нужны Docker Engine с Compose v2 (`docker compose version`) и Git. Команды ниже выполняются обычным пользователем Linux с уже настроенным доступом к Docker. Trackt не меняет настройки Docker и не добавляет пользователя в системные группы.

```sh
git clone https://github.com/olntn/trackt.git
cd trackt

# Только выделенная папка с проектами, которые разрешено читать/изменять агентам.
export TRACKT_PROJECTS_DIR="$HOME/trackt-projects"
export TRACKT_UID="$(id -u)"
export TRACKT_GID="$(id -g)"
mkdir -p "$TRACKT_PROJECTS_DIR"

docker compose up -d --build --wait
docker compose exec trackt bun run doctor
```

Откройте `http://127.0.0.1:4310`. Начальная сборка скачивает образы и CLI. `doctor` проверяет исполняемые файлы и флаги через `--help`, без входа и обращений к моделям. `--wait` проверяет готовность HTTP-сервиса, а не вход в провайдеры.

Папка проектов должна существовать до запуска: Compose намеренно не создаёт её с владельцем root. Контейнерный пользователь `trackt` не имеет root-доступа. На обычном Linux его UID/GID должны совпадать с владельцем файлов. Если используются нестандартные UID/GID, значения выше учитываются при сборке. Не используйте `TRACKT_UID=0`/`TRACKT_GID=0`, `chmod 777` или запуск CLI от root для устранения проблем с доступом.

Для следующих терминалов сохраните три несекретных значения `TRACKT_PROJECTS_DIR`, `TRACKT_UID`, `TRACKT_GID` в локальный `.env` рядом с `compose.yaml` или экспортируйте их снова. Без них используются `./projects`, UID/GID `1000`. При смене UID/GID существующие именованные тома сохраняют старого владельца: сначала сделайте резервную копию и согласованно перенесите владельца данных; простая пересборка его не меняет.

Если Docker работает на удалённом Linux-сервере, откройте доступ через SSH-туннель с вашего компьютера:

```sh
ssh -N -L 4310:127.0.0.1:4310 user@your-server
```

Затем используйте тот же локальный адрес в браузере. Не открывайте порт для LAN или интернета: в MVP нет авторизации пользователей и поддержки публичного reverse proxy.

## 2. Проверить без модели

```sh
mkdir -p "$TRACKT_PROJECTS_DIR/sample"
git -C "$TRACKT_PROJECTS_DIR/sample" init
TRACKT_MODE=mock docker compose up -d --wait
```

Создайте задачу с папкой `/workspace/projects/sample`, любым провайдером и обычной инструкцией. Нажмите **Запустить**. Для сценария уточнения добавьте `[ask]` в инструкцию, ответьте в карточке и продолжите. Демо не вызывает CLI и не меняет файлы проекта.

Вернуться к реальным задачам:

```sh
TRACKT_MODE=cli docker compose up -d --wait
```

В Compose режимы используют разные базы: `/var/lib/trackt/mock.sqlite` и `/var/lib/trackt/cli.sqlite`. Переключение режима не удаляет задачи другого режима.

## 3. Войти в CLI самостоятельно

Вход выполняйте только в своём терминале и на официальной странице провайдера. Не вводите ключи, пароли или коды входа в карточки Trackt, `.env`, issue или сообщения помощнику. Образ и CI не содержат учётных данных и не выполняют вход.

### Codex

```sh
docker compose exec trackt codex login --device-auth
```

Откройте выданную CLI ссылку в своём браузере и следуйте инструкциям. Device-code вход должен быть разрешён в настройках вашего аккаунта/рабочего пространства. Если он недоступен, остановитесь и используйте официальный поддерживаемый способ входа для вашей организации; не публикуйте callback-порт и не передавайте помощнику кеш авторизации. [Официальные способы входа Codex](https://learn.chatgpt.com/docs/auth).

### Claude Code

```sh
docker compose exec trackt claude auth login
```

Следуйте интерактивному входу CLI. Если контейнер не открывает браузер, откройте напечатанную ссылку самостоятельно на своём компьютере; завершайте проверку в этом же терминале. Команда по умолчанию использует вход через Claude, отдельная опция Console меняет способ оплаты. [Официальная документация входа Claude Code](https://code.claude.com/docs/en/authentication).

CLI сохраняют вход и сессии в отдельном именованном томе `trackt-cli-home`. Это **домашняя папка контейнера**, а не смонтированный домашний каталог хоста. Сохраняются и `.codex/`, и `.claude/`, и `.claude.json`. Копирование всего `$HOME` хоста, SSH-агента и Docker socket в контейнер не требуется и не предусмотрено.

## 4. Подключить рабочий проект и разрешения

Поместите доверенный проект внутрь `$TRACKT_PROJECTS_DIR`. Например, `$TRACKT_PROJECTS_DIR/my-project` доступен контейнеру как `/workspace/projects/my-project`. В карточке задачи указывайте **контейнерный абсолютный путь**, а не путь хоста. Для Codex нужен Git-репозиторий. В образ входят Git, Bun, Node и ripgrep; языковые инструменты вашего проекта, например Python, Java или системные библиотеки, при необходимости добавляются в собственную производную сборку.

Перед первым изменением проверьте права и откройте нужный CLI вручную:

```sh
docker compose exec --workdir /workspace/projects/my-project trackt sh -c 'id; test -r . && test -w . && git status --short'
# Выберите один из провайдеров:
docker compose exec --workdir /workspace/projects/my-project trackt codex
docker compose exec --workdir /workspace/projects/my-project trackt claude
```

Подтверждайте доверие только известному проекту. Сделайте Git-коммит или резервную копию перед агентными изменениями. Для первой задачи в Trackt выберите ручной запуск и попросите кратко описать структуру проекта без изменений; затем попробуйте небольшое обратимое изменение в отдельной ветке.

- **Codex:** Trackt задаёт `workspace-write` и `on-request`. Доступные обычные операции внутри рабочей папки могут выполняться в нативной песочнице; операции, требующие дополнительного разрешения, не подтверждаются автоматически.
- **Claude Code:** Trackt оставляет режим разрешений `default`. Чтобы регулярная задача могла редактировать файлы без интерактивного подтверждения каждого действия, настройте разрешения **самостоятельно** через `/permissions` в интерактивном Claude для этого проекта. Выбирайте только необходимые Read/Edit-пути, например исходники конкретного проекта, и конкретные проверенные команды, например `bun test`. Проверьте содержание самой команды/скриптов проекта перед сохранением разрешения. Не разрешайте произвольный shell, всю файловую систему или все инструменты.
- Карточка Trackt принимает уточнение **по задаче**, а не системное разрешение CLI. Нативный запрос разрешения приводит к **Блокировке**. Проверьте причину в терминале, затем начните новую попытку. Не запускайте одну сессию одновременно в Trackt и интерактивном CLI.

### Если нативная песочница не запускается в Docker

В образ включены `bubblewrap` и `socat`, однако Linux namespaces, seccomp, AppArmor и особенности Docker/ядра могут не позволить вложенную песочницу. Поэтому успешные `doctor` и mock-тест не доказывают возможность реальных агентных команд на конкретном хосте.

При сообщениях `Operation not permitted`, `bwrap`, `sandbox` или запрете namespace:

1. Оставьте проблемную задачу остановленной; сохраните текст ошибки без секретов.
2. Проверьте документацию [песочницы Codex](https://learn.chatgpt.com/docs/sandboxing) или [песочницы Claude Code](https://code.claude.com/docs/en/sandboxing) и требования вашего хоста с администратором.
3. Используйте среду Linux/VM, где нативная песочница поддерживается, или выполняйте заблокированные действия вручную в доверенной среде. Интерфейс и демо можно продолжать использовать в контейнере.

Trackt не включает `privileged`, `seccomp=unconfined`, дополнительные capabilities, режим обхода разрешений или ослабление вложенной песочницы. Документация провайдеров описывает и ослабляющие настройки; они не применяются этим проектом автоматически. Наличие контейнера само по себе не делает инструкции, плагины или смонтированные проекты безопасными. Все смонтированные проекты доступны одному контейнерному пользователю; для недоверенных друг другу проектов нужны отдельные экземпляры/тома/маунты.

## Данные, остановка и обновления

- `trackt-data` → `/var/lib/trackt`: SQLite, история задач и ответы; данные не зашифрованы.
- `trackt-cli-home` → `/home/trackt`: CLI-настройки, вход и история сессий; считайте этот том секретным.
- Выделенная папка хоста → `/workspace/projects`: реальные файлы проектов, изменения сохраняются на хосте.

```sh
docker compose logs --tail=100 trackt
docker compose stop                 # корректная остановка с SIGTERM
docker compose start                # продолжить работу
# Удалить контейнер, оставив именованные тома:
docker compose down
```

Не добавляйте `--volumes`/`-v` к `down`, если хотите сохранить задачи и вход. После аварии проверьте результаты файловых изменений до повтора задачи. Не запускайте несколько экземпляров Trackt с одной SQLite или одной CLI-сессией. Расписание действует только пока работает контейнер и хост; `restart: unless-stopped` запускает сервис после обычного перезапуска Docker, если вы не остановили его вручную.

Резервную копию делайте при остановленном сервисе, сохраняя одновременно базу и CLI-сессии:

```sh
docker compose stop
mkdir -p backup/data backup/cli-home
chmod 700 backup backup/data backup/cli-home
docker compose cp trackt:/var/lib/trackt/. backup/data/
docker compose cp trackt:/home/trackt/. backup/cli-home/
docker compose start
```

Не коммитьте `backup/` и не загружайте его в публичные сервисы: там могут быть токены входа, инструкции и ответы. Проекты копируются отдельно. Docker-тома не являются резервной копией от удаления диска или хоста.

Обновление исходников/закреплённых версий выполняется пересборкой `docker compose up -d --build --wait` после проверки изменений. CLI не самообновляются внутри работающего контейнера. Обычный `docker compose down`/пересоздание сохраняет оба тома.

## Версии и проверки

Зафиксированные версии этой сборки:

- Bun `1.4.2`, официальный образ `oven/bun:1.4.2-debian`
- Node `24.21.0`, официальный образ `node:24.21.0-bookworm-slim` ([официальный список тегов](https://github.com/docker-library/official-images/blob/master/library/node))
- Codex CLI `@openai/codex@0.162.0`
- Claude Code `@anthropic-ai/claude-code@2.1.295`

CLI устанавливаются из официального npm registry с платформенными optional dependencies; для Claude выполняется официальный postinstall. Установка пакетов проходит непривилегированным пользователем. У версий пакетов и прямых платформенных зависимостей фиксированные номера, зависимости Trackt берутся из `bun.lock`. Базовые образы закреплены версионными тегами, не digest; Debian security-пакеты могут обновляться между сборками. Это повторяемая сборка по версиям, но не обещание побайтовой идентичности.

Источники: [Codex CLI](https://learn.chatgpt.com/docs/codex/cli), [опубликованный Codex 0.162.0](https://registry.npmjs.org/@openai/codex/0.162.0), [установка Claude Code](https://code.claude.com/docs/en/setup#install-with-npm), [опубликованный Claude Code 2.1.295](https://registry.npmjs.org/@anthropic-ai/claude-code/2.1.295).

Workflow `Container smoke` собирает образ на Linux/amd64, проверяет non-root, версии обоих CLI, `doctor`, права записи в смонтированный проект, HTTP/Host/Origin, создание и mock-выполнение задачи, затем пересоздаёт контейнер и проверяет сохранность задачи, результата и маркера CLI-home. Отдельный сценарий убивает контейнер через SIGKILL и проверяет повторный запуск с той же базой. CI не входит в аккаунты и не обращается к моделям.

При разработке обе закреплённые npm-версии установлены и проверены через `--version`, `--help` и `bun run doctor` в Linux с пустым временным HOME. Дополнительно прошли свежие `bun install --frozen-lockfile --ignore-scripts` и production build, запуск точного набора runtime-файлов без `node_modules`, mock API-сценарий и сохранность SQLite после обычной остановки и SIGKILL процесса. Эти проверки выполнены вне Docker. Полную сборку Docker в среде разработки выполнить нельзя: здесь нет Docker/Podman. До зелёного запуска workflow образ не считается проверенным end-to-end. Другие архитектуры и реальные авторизованные модельные запуски отдельно не проверены.
